# 系統設計文件

## 目標與範圍

讓臺南市使用者快速查看附近有收錄的公廁場所，辨識公廁類型，並在地圖上探索或透過 Google Maps 瀏覽地點。資料來源為建置時打包的政府資料快照；本系統不提供即時開放狀態、道路導航、街道地址查詢、使用者帳號或後端資料同步。

## 主要使用流程

1. **啟動及定位**：讀取內建場所資料，詢問定位權限，取得位置後顯示最近 50 個場所。拒絕權限時顯示說明與再次授權入口；定位服務未開啟時提供前往定位設定的入口。
2. **清單查看**：每個場所顯示整理後的名稱、縣市／鄉鎮／村里、全部不重複的類型標籤及直線距離。點卡片開啟地圖並移到該點；點「Google Maps 瀏覽」交給外部 App 或瀏覽器。
3. **地圖探索**：在視野內顯示全部收錄場所，依目前畫面距離聚合標記。點相近地點的數字標記逐步放大；同座標多場所可由清單選擇。點單一場所顯示卡片，按 × 或點地圖空白處關閉。右下角定位按鈕置中使用者位置並至少放大到 19 級。
4. **外觀偏好**：透過齒輪進入設定，立即切換系統／淺色／深色模式與六色或 Hue 自訂主題；設定儲存在裝置內，Android 上一頁鍵返回主畫面。

## 頁面與狀態

| 畫面／狀態 | 內容與行為 |
| --- | --- |
| 載入中 | 顯示讀取提示；資料於背景讀取。 |
| 資料錯誤 | 顯示載入失敗提示，避免將損毀資產當成零筆資料。 |
| 尚無定位 | 顯示允許定位／開啟定位設定入口；不以未知位置計算距離。 |
| 清單 | 最近 50 個場所及「重整」；距離隨位置更新。 |
| 地圖 | 使用者位置、各場所標記、聚合數字及資料卡片；手勢可拖曳、縮放。 |
| 設定 | 顯示模式、預設色、Hue 滑桿、資料來源連結與返回按鈕。 |

## 資料與互動設計決策

- 原始 **4,449 筆**資料可能是同一場所的男廁、女廁等紀錄；轉檔時僅在「座標、行政區域、去除對應廁所類型尾字後的完整名稱」一致時合併，現有快照整理為 **2,383 個場所**。不同樓層或不同場所即使共用座標仍分開，避免誤導。
- 「員工混合廁」維持獨立標籤，不與一般「混合廁所」混為一談；其他來源欄位不會臆測出無障礙或營業狀態。
- 地圖「數字聚合」與離線資料「場所合併」是不同步驟：前者只為避免地圖過於擁擠，會隨縮放改變；後者在建置前完成並影響清單的筆數。
- 聚合半徑是 **24 dp 畫面距離**，不是固定公尺；圖示允許輕微重疊。相同座標無法靠放大拆開，因此提供場所清單。
- 地圖標記使用自訂圖示；底圖保留 OpenStreetMap 出處。只有使用者主動點擊外部瀏覽按鈕才開啟 Google Maps。
- 定位權限、網路與裝置服務可能不可用，因此介面提供相應提示；內建資料不依賴即時 API。

## 後續維護邊界

新版資料需先經 `tools/prepare_toilets.py` 驗證及產出 JSON，再重新建置 App。若資料集欄位名稱、座標精度或「員工混合廁」等標記方式改變，需同步調整轉檔規則、測試與文件；執行中的 App 不會自行下載新版資料。
